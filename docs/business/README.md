# Finland Rail analytics delivery pack

> **Portfolio simulation.** This folder models how an internal analytics team could deliver the Finland Rail Monitoring System. It does not claim employment by, a commission from, or access to internal systems of Fintraffic, VR, Statistics Finland, Microsoft, or any other organisation.

The application and historical analysis use public data. The stakeholder roles, backlog, change request, incident and delivery workflow below are deliberately simulated so the repository demonstrates a realistic Data/BI Analyst lifecycle without inventing commercial experience.

| Artifact | Purpose |
| --- | --- |
| [Business requirements](requirements.md) | Problem, users, KPI contract, scope and acceptance criteria |
| [Backlog](backlog.md) | Prioritised, issue-ready work with dependencies and Definition of Done |
| [Change request CR-001](change-requests/CR-001-regional-delay-threshold.md) | Simulated stakeholder request carried from analysis to release |
| [Traceability matrix](traceability.md) | Requirement → code → test → documentation evidence |
| [Stakeholder delivery](stakeholder-delivery.md) | Evidence-backed findings and decision support |
| [Incident INC-001](../incidents/INC-001-empty-daily-partition.md) | Simulated data-quality incident and preventive control |

Real Git commits and GitHub Issues record only work actually performed in this repository. They are not backdated or presented as historical client delivery.
